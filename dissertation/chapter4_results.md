# Chapter 4: Results and Discussion

## 4.1 Introduction

This chapter presents the experimental results obtained from the proposed explainable log anomaly detection framework. The performance of the Isolation Forest model is analysed using the engineered HDFS log features, followed by an interpretation of the detected anomalies. SHAP explainability is then used to identify the most influential features contributing to anomaly predictions.
## 4.2 Anomaly Detection Results

The Isolation Forest model was applied to the processed HDFS log dataset containing 2,000 log entries.

The model identified **88 anomalous log entries** while classifying **1,912 log entries** as normal observations. This indicates that approximately 4.4% of the dataset was detected as anomalous, which is consistent with the selected contamination parameter used during model training.

The detected anomalies were further analysed using statistical summaries and visualisations to better understand their characteristics.
## 4.3 Log Level Analysis

The distribution of log levels was examined to understand the composition of the HDFS dataset. The majority of log entries belonged to the **INFO** level, indicating that most system activities represented normal operational events.

Only a small proportion of log entries contained warning or error messages. This observation is expected because production systems generally generate significantly more informational logs than abnormal events.

The dominance of INFO messages demonstrates that the dataset largely represents normal system behaviour, making anomaly detection a suitable approach for identifying unusual log events.
## 4.4 Component Analysis

The detected log entries were also analysed according to their Hadoop system components.

The analysis showed that components such as **DataNode**, particularly **DataNode$DataXceiver**, appeared most frequently within the dataset. This is expected because DataNode components are responsible for continuous data transmission and storage operations within the Hadoop Distributed File System.

Components with lower frequencies generally represented specialised system functions. Understanding the distribution of system components provides additional context when interpreting anomaly detection results.
## 4.5 Message Length Analysis

Message length was analysed to determine whether anomalous log entries differed from normal system logs.

The experimental results showed that the **average message length of normal log entries was approximately 94 characters**, whereas the **average message length of anomalous log entries was approximately 127 characters**.

This observation suggests that anomalous log messages generally contain more detailed or unusual information than normal operational logs. Longer log messages may indicate abnormal system behaviour, additional diagnostic information, or unexpected execution paths. Therefore, message length proved to be a useful feature for anomaly detection.
## 4.6 SHAP Explainability Results

SHAP analysis was performed to explain the predictions generated by the Isolation Forest model.

The SHAP summary plot revealed that **message length**, **log level**, **system component**, and the presence of specific log patterns such as packet responders and block identifiers were among the most influential features affecting anomaly predictions.

The explainability analysis demonstrated that the model relied on meaningful characteristics of the log data rather than random patterns. This improves the transparency of the anomaly detection process and provides valuable insights for system administrators when investigating abnormal events.
## 4.7 Discussion

The experimental results demonstrate that the proposed explainable anomaly detection framework successfully identified unusual log events within the HDFS dataset.

The Isolation Forest model detected 88 anomalous log entries while maintaining the majority of observations as normal system behaviour. Analysis of the detected anomalies showed that they generally contained longer log messages and were associated with specific Hadoop system components.

Furthermore, the SHAP explainability analysis increased the transparency of the anomaly detection process by identifying the features that contributed most to the model's decisions. This improves the interpretability of the framework and allows system administrators to better understand why certain log entries are classified as anomalous.

Overall, the combination of Isolation Forest and SHAP provides an effective and interpretable approach for analysing large-scale distributed system logs.
